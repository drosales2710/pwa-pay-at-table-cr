Suggested 10-minute walkthrough

1Guest joins table 7

Open guest link, enter a name, land on the menu.

2Order food + drinks

Add a main and a cocktail. Send to kitchen — items split to kitchen vs bar KDS.

3Kitchen & bar bump

Log in as kitchen (2847) and bar (9156). Advance tickets through the flow.

4Server view

Log in as server (4821). Open table 7 on the floor plan — see the live cart.

5Guardian (optional)

Order alcohol or high-value items to trigger manager approval (PIN 0000).

6Pay at table

Guest checkout — Apple Pay / card / split bill (simulated 1.8s delay).

7Cashier

Cashier portal (5638) shows today’s payments for table 7.

8Admin

Files to send Attach or zip these from the docs/ folder:
  • app-demo.html — this guide (works offline; links need a running server)
  • demo-assets/ — portal screenshots referenced above
  • costa-rica-pat-demo.zip — runnable demo (~550 KB): built app + local API + README

Recipient instructions

  1. Unzip costa-rica-pat-demo.zip
  2. Install Node.js 22+ if needed
  3. Run ./start-demo.sh (macOS/Linux) or npm start inside the folder
  4. Open app-demo.html and click Open guest (table 7)
No public URL by default This demo runs on the recipient's machine at localhost:8443. To demo over the internet temporarily, tunnel port 8443 (e.g. ngrok) and paste the HTTPS URL into the Demo server URL field at the top.

What works vs what is simulated

FeatureDemo behavior
Menu, cart, send-to-kitchenFull flow on table 7; kitchen/bar ticket split by category
Guardian (alcohol / price / qty)Approve or reject with manager PIN; reject rolls back sent lines
Split billFull, equal, or pay-my-items with FIFO settlement
Staff auth + KDS devicesLocal API (/api/v1) with JSON file store; falls back to localStorage if server is down
PaymentsSimulated — 1.8s delay, no PSP, no SINPE capture
Multi-deviceNot supported — one browser tab is the whole restaurant
Hacienda invoicesUI fields only; not persisted or transmitted
Admin historic reportsToday is live; prior days use demo fixtures
